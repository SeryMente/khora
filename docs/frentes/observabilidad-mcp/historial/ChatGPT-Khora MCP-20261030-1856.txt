La distinción fundamental es que MCP no es solamente un mecanismo de observabilidad. Es una interfaz estandarizada para que aplicaciones de inteligencia artificial accedan a capacidades y contexto proporcionados por sistemas externos.

1. Definición general de MCP

MCP - Model Context Protocol (Protocolo de Contexto de Modelos) es un protocolo abierto de comunicación cliente-servidor que permite conectar aplicaciones de inteligencia artificial con fuentes de información, herramientas y capacidades especializadas.

Su finalidad es establecer una interfaz común para que diferentes plataformas de IA puedan descubrir, comprender y utilizar capacidades externas sin necesitar una integración completamente particular para cada aplicación. [modelcontextprotocol/docs/specification/2026-07-28/architecture/index.mdx at main · modelcontextprotocol/modelcontextprotocol; modelcontextprotocol/docs/docs/2026-07-28/learn/architecture.mdx at main · modelcontextprotocol/modelcontextprotocol]

Un servidor MCP puede proporcionar tres clases fundamentales de capacidades:

Componente
Función
Ejemplo

Proporcionar información y contexto consultable.
Documentación, registros, estado del sistema.

Permitir ejecutar operaciones mediante llamadas estructuradas.
Consultar una base de datos, recuperar un registro, ejecutar un diagnóstico.
Prompts (Indicaciones)
Ofrecer plantillas e instrucciones especializadas reutilizables.
Un procedimiento de diagnóstico o una metodología de revisión.

[modelcontextprotocol/docs/specification/2026-07-28/server/tools.mdx at main · modelcontextprotocol/modelcontextprotocol; modelcontextprotocol/docs/specification/2026-07-28/server/prompts.mdx at main · modelcontextprotocol/modelcontextprotocol; modelcontextprotocol/docs/specification/2026-07-28/basic/index.mdx at main · modelcontextprotocol/modelcontextprotocol]

La arquitectura distingue tres participantes:

Host: aplicación que utiliza el modelo y administra las conexiones.

Client: componente que establece la comunicación MCP.

Server: sistema que proporciona los recursos, herramientas y prompts.

Por tanto, el modelo no necesita conectarse directamente al servidor: la plataforma que lo aloja media la interacción y administra la conexión y sus permisos.
